The payment integration incorrectly calculates transaction amounts due to floating-point precision issues and fails to handle invalid input gracefully, leading to incorrect charges and server errors.

1. Incorrect Transaction Amount Due to Floating-Point Precision

high

Failed checks: exact_amount_19_99, exact_amount_1_15

What happened

The system charged customers 0.01 USD less than the expected amount (e.g., 19.98 USD instead of 19.99 USD, and 1.14 USD instead of 1.15 USD).

Likely cause

The `format_amount` function uses floating-point arithmetic (`amount * 100`) and then truncates the result to an integer (`int(...)`) before dividing by 100. This causes precision loss for amounts like 19.99, where `19.99 * 100` might result in `1998.99999...`, which `int()` truncates to `1998`, leading to a final charge of `19.98`.

Suggested fix

Use the `Decimal` type for all financial calculations to maintain precision and ensure correct rounding to the nearest cent, as demonstrated in the 'fixed' branch of the `format_amount` function.

def format_amount(amount: float) -> str:
    return str(Decimal(str(amount)).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP))

2. Unhandled Invalid Input Leading to Internal Server Errors

high

Failed checks: negative_amount, zero_amount

What happened

When attempting to process negative or zero amounts, the system returned an HTTP 500 Internal Server Error instead of a clean HTTP 400 Bad Request.

Likely cause

The `checkout` endpoint lacks explicit validation for non-positive amounts before attempting to create a PayPal order. Additionally, it re-raises `PayPalError` exceptions directly without converting them into a client-friendly HTTP 400 response, causing the application to crash with a 500 error when PayPal rejects the invalid amount.

Suggested fix

Implement pre-validation for the `amount` in the `checkout` endpoint to ensure it's greater than zero, returning an HTTP 400 if not. Also, catch `PayPalError` exceptions and translate them into a generic HTTP 400 response to prevent internal details from leaking and provide a better user experience.
