The payment integration has two critical issues: incorrect calculation of payment amounts leading to undercharging customers, and a lack of proper input validation and error handling for invalid payment amounts, resulting in server errors.

1. Incorrect payment amount due to floating-point precision errors

high

Failed checks: exact_amount_19_99, exact_amount_1_15

What happened

The system charges customers 0.01 USD less than the displayed amount. For example, a 19.99 USD charge becomes 19.98 USD, and 1.15 USD becomes 1.14 USD.

Likely cause

The `format_amount` function, when bugs are enabled, uses `int(amount * 100)` to convert the amount to cents. This approach truncates floating-point numbers (e.g., 19.99 * 100 results in 1998.99999..., which `int()` converts to 1998), effectively rounding down and losing a cent.

Suggested fix

Use Python's `Decimal` type for all monetary calculations to ensure exact precision and correct rounding. The `Decimal` type prevents floating-point inaccuracies that can lead to financial discrepancies.

def format_amount(amount: float) -> str:
    return str(Decimal(str(amount)).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP))

2. Server crashes with 500 for invalid payment amounts

medium

Failed checks: negative_amount, zero_amount

What happened

When attempting to process a negative or zero payment amount, the server responds with an HTTP 500 Internal Server Error instead of a clean HTTP 400 Bad Request. This exposes internal server details and provides a poor user experience.

Likely cause

The `/checkout` endpoint lacks explicit input validation for the `amount` field before calling the PayPal API. When PayPal rejects the invalid amount, the `PayPalError` is caught but then re-raised directly (due to `if BUGS: raise`), which FastAPI converts into a generic 500 error.

Suggested fix

Implement robust input validation at the API entry point to ensure the `amount` is positive before interacting with the payment provider. Additionally, catch specific payment provider errors and translate them into client-friendly HTTP 400 responses without exposing internal error details.

@app.post("/checkout")
def checkout(req: CheckoutRequest):
    if req.amount <= 0:
        raise HTTPException(status_code=400, detail="Amount must be greater than zero")

    try:
        order = paypal.create_order(format_amount(req.amount), req.currency)
    except PayPalError as e:
        raise HTTPException(status_code=400, detail="Payment provider rejected the request")

    approve_url = next(
        (l["href"] for l in order.get("links", []) if l["rel"] in ("approve", "payer-action")),
        None,
    )
    return {"order_id": order["id"], "status": order["status"], "approve_url": approve_url}
